# Automatic annotated recording review

Session results now show the saved recording with a synchronized MediaPipe body skeleton. The player supports pause/play, seeking, skeleton visibility, correction markers, and cards that jump to a measured moment. Amber/red highlights identify the affected joints; each card contains the cue, measured value, target, and coaching instruction.

New training recordings retain the MediaPipe poses already detected during capture. When recording stops, the final session scorer also returns the exact scored phase moments and affected joints. These poses and corrections are saved beside the private video before the result screen opens. Reviewing a new recording reads the retained feedback without running the pose model over the MP4 again. A cue is flagged only below 0.8, with red below 0.35. Loading, contact, and follow-through errors use their corresponding phase timestamps. Unknown camera views and unreliable joints are not treated as mistakes. The UI distinguishes no tracked pose, no measurable complete action, and no corrections among measurable actions.

CameraX preview, image analysis, and video share a viewport and target rotation. Analysis pixels are cropped and rotated before detection. Video mirroring is explicitly disabled; replay uses original unmirrored image coordinates. The front-camera preview retains its mirror behavior. Raw sensor timestamps are preserved separately from the detector's strictly increasing clock. Recorder status durations calibrate sensor timestamps to the zero-based MP4 timeline using a median of recent observations. Replay clips poses and corrections to the finalized duration. Overlay lookup rejects stale/missing poses, and seeking follows the actual player position. The overlay uses a centered fit transform.

New feedback lives in `filesDir/video_reviews`. Atomic writes, source size/modification checks, skill identity, and schema version guard the stored data. Clearing disposable app cache does not remove new feedback. Saving reads video metadata only, without frame decoding or additional pose inference. Session deletion/eviction removes its feedback. Sidecars are excluded from Android cloud backup and device transfer. Neither landmarks nor recordings are added to cloud submissions; coach sharing retains the existing measured-result contract.

Local session saving no longer awaits the cloud mirror. A process-lifetime queue performs best-effort score uploads in the background and preserves upload/delete order. Each operation retains its original account uid and is skipped if that account is no longer signed in. A Firestore transaction preserves the current coach share list when explicit submission races a background upload. Explicit Send to coach still awaits its own submission transaction and reports the outcome.

Older recordings made before poses were retained still use automatic one-time MP4 analysis, labelled “Analyzing this older recording…”. Their analysis cache is reused afterward. Legacy CPU analysis took about 85 seconds for a 12.142-second clip on the Infinix X6833B; this delay is removed from new recordings. Final rep scoring, encoder finalization, and local writes still occur after Stop, so this does not promise zero processing time.

Validation: 31 focused unit tests passed, covering retained replay timing/clipping/gaps, exact final scores and phase values, saving feedback before finishing the session, guided capture/view policy, and background uploads under stalled-network/account-switch/failure conditions. Build and lint passed with no errors.

Both device tests passed on the Infinix X6833B. The retained-feedback test submitted three fixture images from a disposable copy of an existing recording to the production live-stream MediaPipe detector, retained two real poses, saved/read feedback in 118 ms, and displayed the ready skeleton controls in 365 ms without legacy analysis. Seeking and play/pause worked, and durable feedback remained readable after removing the fixture's disposable cache. This is a small retained-data fixture, not an end-to-end latency measurement for a long training session. The hardware capture test recorded/finalized a 2.665-second front-camera video, verified that video and cropped analysis were both 480 × 640, calibrated the recorder clock, and saved/read an empty-pose outcome in 35 ms without inference. Finalization required an explicit idle synchronization in the device test; that test synchronization was corrected after its initial timeout. Physical timing of live corrections during a full drill remains a manual check; the exact scoring/phase mapping is unit-tested.
